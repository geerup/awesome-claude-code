## 3. Technical SEO Findings

### Finding 1: hreflang implementation for Arabic and English

- Issue: The live AR and EN class pages exist at paired URLs
  (/ar/class/design-style/bassam-fattouh-teaches-makeup and /en/class/...). Whether the
  hreflang tags are correctly implemented on both pages is not confirmed from a read-only
  crawl without Search Console access.
- Required implementation: Each page must carry a full hreflang set in the HTML head.

  AR class page must include:
  ```
  <link rel="alternate" hreflang="ar" href="https://www.maharat.com/ar/class/design-style/bassam-fattouh-teaches-makeup" />
  <link rel="alternate" hreflang="en" href="https://www.maharat.com/en/class/design-style/bassam-fattouh-teaches-makeup" />
  <link rel="alternate" hreflang="x-default" href="https://www.maharat.com/ar/class/design-style/bassam-fattouh-teaches-makeup" />
  ```
  EN class page must carry the same three tags with identical URLs.
  The x-default should point to the AR version as Arabic is the primary language.

- Same pattern applies to the /ar/plans and /en/plans pair.
- Impact: Without correct hreflang, Google may serve the wrong language version to Saudi and
  GCC Arabic users, diluting the Arabic-first SEO investment.
- Fix: conversion-engineer to implement the above tags in the page head, or in the sitemap
  hreflang entries, on both pages of each pair.

### Finding 2: /library/ path returns 403

- Issue: The /library/ path used for the makeup campaign previously returns 403. Confirmed
  from the instructor profile note (crawl 2026-06-05). Any internal link, any external
  backlink, any email or social link pointing to /library/... paths will land on an error,
  not the class page.
- Impact: High. A 403 blocks indexation of that path, drops any link equity flowing to it,
  and breaks the user journey for any click that reaches it. If the class was previously
  promoted under /library/, those external links now dead-end.
- Fixes:
  - Primary: redirect any /library/design-style/bassam-fattouh-teaches-makeup (and any
    variant) with a 301 to the live /class/ equivalent. Conversion-engineer to implement.
  - Audit: check all internal links, email templates, and campaign URLs in this run for any
    /library/ reference and replace with the confirmed /class/ path before any send or
    publish.
  - Open item: verify whether any active backlinks or social posts still point to the
    /library/ path. Search Console access would surface this directly.

### Finding 3: RTL correctness on the class page

- Issue: The class page is confirmed live but RTL rendering has not been audited without a
  live browser or crawl tool.
- Required checks (for conversion-engineer to audit and fix):
  - The AR class page (dir="rtl") must render all Arabic text right-to-left without
    reversal artifacts.
  - Mixed AR/EN strings (for example instructor name in Latin script within Arabic copy)
    must use Unicode bidi-override or CSS direction correctly so neither block breaks.
  - Western numerals (chapter numbers, price reference) must display correctly within RTL
    context. No Eastern Arabic numerals.
  - The page layout (navigation, breadcrumbs, CTAs, lesson list) must mirror correctly in RTL
    view. A misaligned RTL layout is a ranking signal issue on Core Web Vitals (layout shift)
    and a conversion issue.
  - Schema JSON-LD blocks in the HTML must carry the correct language and direction
    attributes.
- Impact: Medium to high. RTL rendering failures hurt user experience, increase bounce rate,
  and signal poor page quality to Googlebot.
- Fix: conversion-engineer runs a full RTL audit on the AR class page and the AR plans page
  before the campaign goes live.

### Finding 4: Sitemap coverage for AR and EN class pages

- Issue: It is unconfirmed whether the AR class page and EN class page are included in the
  XML sitemap and whether the sitemap is submitted to Google Search Console.
- Required state:
  - Both /ar/class/design-style/bassam-fattouh-teaches-makeup and /en/class/... must appear
    in the XML sitemap.
  - The sitemap must carry hreflang annotations if using the sitemap method for hreflang
    (alternative to the HTML head method in Finding 1; do not implement both methods for the
    same URL, use one consistently).
  - The plans pages (/ar/plans, /en/plans) should also be in the sitemap if not already.
  - The /library/ path, if it 403s, must not appear in the sitemap. A sitemap entry pointing
    to a 403 is a crawl waste and a coverage error in Search Console.
- Impact: Missing sitemap entries slow indexation. A 403 in the sitemap flags a coverage
  error that can reduce crawl budget allocation.
- Fix: conversion-engineer or the site owner audits and updates the sitemap. Block any
  /library/ reference. Confirm sitemap submission in Search Console.

### Finding 5: Crawlability and indexation status

- Issue: Search Console access is not granted to this agent. Indexation status,
  crawl coverage, and any existing manual actions or penalties on the class pages cannot be
  confirmed without it.
- Impact: Medium. Campaign SEO plans on the assumption both class pages index cleanly.
  If there is a noindex tag, a crawl block in robots.txt, or a coverage error, organic
  discovery fails regardless of the keyword and on-page work done here.
- Fix: surface this as an open item at the human gate. Request Search Console read access for
  this campaign so the seo-specialist can confirm indexation, query impressions for the class
  URLs, and monitor coverage errors during the flight.

### Finding 6: Page speed and Core Web Vitals

- Issue: Page speed and Core Web Vitals scores for the class pages are not available without
  a live audit tool (PageSpeed Insights or Search Console CWV report).
- Impact: Core Web Vitals are a confirmed Google ranking signal. A slow or visually unstable
  class page on mobile (the primary access mode for Saudi GCC users) hurts both rank and
  conversion.
- Required checks (conversion-engineer):
  - LCP (Largest Contentful Paint) on the AR class page mobile view: target under 2.5
    seconds. Class pages with hero video or large images are high-risk.
  - CLS (Cumulative Layout Shift): target under 0.1. RTL layout and late-loading assets are
    a CLS risk.
  - INP (Interaction to Next Paint): target under 200ms.
  - If a Bassam Fattouh portrait or class hero image is confirmed and added (currently OPEN
    ITEM on assets), the image must be sized, compressed, and served with a CDN. No
    unoptimized large image on the class page.
- Fix: conversion-engineer runs a PageSpeed audit on both AR and EN class pages after the
  page build and before campaign launch.

### Finding 7: Canonical tags

- Issue: The AR and EN class pages are separate URLs and should not be marked as duplicates
  of each other. Each must carry a self-referencing canonical tag.
- Required state:
  - /ar/class/design-style/bassam-fattouh-teaches-makeup must carry:
    `<link rel="canonical" href="https://www.maharat.com/ar/class/design-style/bassam-fattouh-teaches-makeup" />`
  - /en/class/... carries its own self-referencing canonical.
  - No cross-language canonical (the EN page must not canonicalize to the AR page or vice
    versa).
- Impact: An incorrect or missing canonical can cause Google to collapse the two pages and
  index only one, losing the language-specific ranking signal.
- Fix: conversion-engineer confirms canonical implementation on both pages.
