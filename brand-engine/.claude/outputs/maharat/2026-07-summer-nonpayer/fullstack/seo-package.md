## 2. On-Page Optimization Specs

These are specs with copy-overlay slots only. The copywriters fill every bracketed slot with
final approved copy. No final copy is written here. All specs are Arabic-first; the AR page is
primary for each pair. The EN page mirrors the structure in English and is the hreflang
alternate.

Shared rules for every page:
- Titles: no em dashes, no tatweel, Western numerals, max 60 characters.
- Meta descriptions: no em dashes, no accreditation language, max 155 characters, Arabic-first
  framing.
- Schema: no accreditation anywhere. educationalCredentialAwarded, if used, must read exactly
  "شهادة إتمام" in Arabic schema or "completion certificate" in English schema. Never
  "accredited" or any equivalent.
- Internal links: anchor text copy slots, never generic "click here." All links must resolve
  to confirmed /class/ paths, not /library/ paths.

### Finding T-01: hreflang implementation for all AR/EN page pairs

Issue: The campaign operates 16 confirmed pages across 8 AR/EN class pairs plus the plans pair,
plus the new Summer of Skills landing pair. Whether hreflang is correctly implemented on any of
these pairs is unconfirmed without Search Console access or a live crawl tool. The Elda
Choucair pages are confirmed live but not in the site nav, increasing the risk they lack
correct hreflang.

Required implementation for each AR/EN pair: Each page in a pair must carry a complete
hreflang set in the HTML head.

Example for the music pair:

AR page (/ar/class/music/ragheb-alama-teaches-music-and-performance) must include:
  hreflang="ar" pointing to the AR URL
  hreflang="en" pointing to the EN URL
  hreflang="x-default" pointing to the AR URL (Arabic is primary)

EN page (/en/class/music/...) must carry the same three tags with identical URLs.

The same three-tag pattern applies to:
- All seven class page pairs (music, cooking, acting, makeup, business, styling, marketing)
- The plans pair (/ar/plans and /en/plans)
- The new Summer of Skills landing pair (/ar/summer and /en/summer)

x-default should point to the AR URL on every pair, because Arabic is the primary language.

Impact: Without correct hreflang, Google may serve the wrong language version to Saudi and GCC
Arabic users, diluting the Arabic-first SEO investment and misrouting English-language GCC
traffic. For the campaign's 16 confirmed pages this is a high-impact risk.

Fix: conversion-engineer implements and confirms hreflang on all page pairs. Implement
consistently in either the HTML head method or the sitemap method, not both on the same URL.

### Finding T-03: RTL correctness on AR class pages and new landing page

audited live. This is a recurring risk for any new page build and for any existing page that
receives new content.

Required checks (conversion-engineer to audit and confirm for each AR page):

- All Arabic text renders right-to-left without reversal artifacts.
- Mixed AR/EN strings (instructor names in Latin script within Arabic copy, chapter names in
  English within an AR page context) use Unicode bidi-override or correct CSS direction so

- Western numerals (chapter numbers, plan durations) display correctly within the RTL context.
  No Eastern Arabic numerals anywhere on any page.
- Page layout (navigation, breadcrumbs, CTAs, chapter lists, plan tier cards) mirrors correctly

quality to Googlebot, and are a CLS risk in Core Web Vitals.

### Finding T-06: Canonical tags on all page pairs

Issue: The AR and EN class pages are separate URLs serving distinct language audiences. Each
must carry a self-referencing canonical tag. Without this, Google may collapse a language pair
and index only one version, losing the language-specific ranking signal.

Required state for each page:

- Each EN page carries: canonical href = its own full EN URL.
- No cross-language canonical (the EN page must not canonicalize to the AR page or vice versa).
- This applies to all 16 confirmed pages and both Summer of Skills landing pages.

Impact: An incorrect or missing canonical can eliminate half the language-specific ranking
investment for a given domain.

Fix: conversion-engineer confirms canonical implementation on all pages as part of the
campaign build.

### Finding T-08: Page speed and Core Web Vitals

Issue: Page speed and Core Web Vitals scores for the campaign pages are not available without
a live audit tool. The new Summer of Skills landing page is an additional surface that will
need a speed audit on build.

Impact: Core Web Vitals are a confirmed Google ranking signal. The primary access mode for
Saudi GCC users is mobile. A slow or visually unstable page on mobile hurts rank and
conversion simultaneously.

Required checks (conversion-engineer, after build):
- LCP (Largest Contentful Paint) on each AR page mobile view: target under 2.5 seconds. Class
  pages with hero video or large images are high-risk.
