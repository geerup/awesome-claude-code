# MJML component library (Maharat email build)

The MJML authoring layer for the slotted email build. The 12+1 core components of
`context/profiles/maharat/email-design-system.md` plus the 3 multi-instructor digest modules (16 in all) as
`mj-include` fragments, a shared head with the brand fonts, and a base template that composes them.
It is the "both" path: author in MJML and compile, or hand-build, the same slotted output.

## The source-of-truth rule

The committed slotted HTML (the per-email files under the campaign output, for example
`outputs/2026-06-bassam-fattouh-makeup/email-html/e1.ar.html`) is the SOURCE OF TRUTH. It carries
the full slot contract that the gates read: `data-ortto-module`, `data-slot`, `data-role`,
`data-lang`, `data-copy-id`, `data-link-slot`, and the MSO VML CTA roundrect fallback. MJML emits
brand-correct, RTL table HTML, and the compiled output must equal the committed slotted HTML. MJML
does not natively carry arbitrary `data-*` attributes onto its output cells, so those slot
attributes are applied to match the source of truth; MJML is the convenience, the slotted HTML is
the contract. If the two ever diverge, the committed slotted HTML wins and the MJML is corrected.

## Compile

```
cd .claude/skills/05-build-launch/email-html-build/mjml
npm install            # once, installs mjml locally (see "Approved dependency")
npx mjml base-template.mjml -o ../build/base-template.html
npx mjml --validate base-template.mjml      # structure check, writes nothing
```

`node_modules/`, `package-lock.json`, and the compiled `build/` output are gitignored: they are a
machine-local cache and a generated artifact, regenerated by `npm install` and `npx mjml`. Only
the MJML sources and `package.json` are committed.

## Files

- `package.json`: declares `mjml` as the single devDependency.
- `components/head.mjml`: the shared head, brand fonts via the Ortto-hosted custom-fonts CSS
  (`Lyon Arabic Display`, `Acumin Pro`), brand attributes, the mobile rules.
- `components/01-logobar.mjml` ... `13-footer.mjml`: the 12+1 core components (LogoBar, Hero,
  SectionHeading, BodyCopy, Button, PromoLine, Divider, ListBlock, ClassCardGrid, FeatureImage,
  EventDetails, BillingNotice, Footer), each mapped to its slot attributes in a header comment.
- `components/14-lessoncardgrid.mjml`, `15-issueindex.mjml`, `16-memberwin.mjml`: the 3
  multi-instructor digest modules (the extension set), used only for the multi-instructor format
  (a Skill Path, a themed roundup, an occasion sale, a recommendation). The angle method is
  `context/profiles/maharat/multi-instructor-angles.md`. LessonCardGrid uses `mj-raw` to carry the live copy slots
  the same way ClassCardGrid does; the renderer emits the full grid and is the source of truth.
- `base-template.mjml`: composes a representative email from the includes.

## Per-email module selection (parity with the renderer)

A 7-step sequence is not one fixed layout: each email selects which body modules sit between the
SectionHeading and the single Button. `scripts/email_render.py` drives this from the spec (an
explicit per-email `modules` list, for example `["body","list","feature","promo"]`, or inferred
from the keys the email supplies). The MJML path mirrors this by including only the component
fragments that email uses, in the same order, between `03-sectionheading.mjml` and
`05-button.mjml`. The always-present chrome (head, `01-logobar`, `02-hero`, the single
`05-button`, `13-footer`) stays constant; `08-listblock`, `10-featureimage`, `06-promoline`, and
`09-classcardgrid` are included per email. For a multi-instructor digest, the extension modules
`15-issueindex` (top, after the SectionHeading), `14-lessoncardgrid` (the in-body offer grid), and
`16-memberwin` (late, before the Button) are included per email, driven by the spec's
`issue_index`, `lesson_cards`, and `member_win` keys. The PromoLine is included only when a real
code exists (never invented); the ClassCardGrid and LessonCardGrid only with status-cleared,
rights-cleared instructors, else omitted and flagged. The committed slotted HTML each renderer
emits remains the source of truth.

## Brand and house rules carried by every component

- Brand constants only: paper `#141414`, panel `#1A1A1A`, emerald `#009975`. The gold `#C4963C`
  and panel `#1c1c1c` are PENDING Ahmed and stay out of customer-facing email; the PromoLine chip
  uses constitution colors until the gold is approved.
- Brand fonts only, via the Ortto custom-fonts CSS: Arabic stack
  `'Lyon Arabic Display','29LT Azer',Tahoma,Arial,sans-serif`, English `'Acumin Pro',Arial,sans-serif`.
  No font binary is embedded or committed (the binaries are gitignored under `.claude/assets/fonts/`).
- One primary CTA per email, near-black `#141414` label on emerald (about 5:1, clears WCAG AA).
  The slotted source adds the MSO VML roundrect for Outlook.
- Live text, never image-only; every image is text-free with descriptive alt; the ClassCardGrid
  carries only status-cleared instructors with rights-cleared covers, else it is omitted.
- No em dash, no en dash, no tatweel, Western numerals only.

## Approved dependency

MJML is an approved build dependency (Ahmed approved 2026-06-17). It is a LOCAL compiler run with
`npx mjml`, NOT an MCP server: it does not go in `settings.json` `enabledMcpjsonServers` and it is
not a generative tool. The Arabic-capability filter that governs generative tools does not apply
to a deterministic HTML compiler. `npm install` was run once and succeeded (mjml 4.18.0, 166
packages). If a network blocks the install, the compile runs in CI or locally and the hand-built
slotted HTML remains the committed source of truth, so the build is never blocked on the compiler.

## How it connects

Part of the `email-html-build` skill (`../SKILL.md`). The compiled or hand-built slotted HTML runs
the email gate stack: skill eval, per-language copy QA by slot, `email-asset-qa` on every image
module, `accessibility-qa`, `compliance-privacy-check`, `brand-qa-reviewer`, then the human gate.
Assembled, never sent.
